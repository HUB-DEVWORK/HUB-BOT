# Ручная проверка бота перед релизом

Прогон всех видимых юзеру экранов и флоу в Telegram. Полный проход занимает 35-45 минут.
Гонять на тест-стенде с мок-панелью, не на бою. Юнит-тесты (`make check`) это не заменяет:
они не ловят сломанную клавиатуру, застрявшую форму или кривой текст на экране.

Понадобится: свой аккаунт (он же админ, id в `APP__OWNER_IDS`), желательно второй аккаунт
для триала/рефералки, доступ на сервер стенда по ssh и в веб-админку `/admin/`.

## Подготовка (5 мин)

```bash
# деплой свежей сборки (из чистого закоммиченного дерева)
./scripts/deploy.sh <user@host> https://<домен-стенда>

# демо-данные: план за 150 руб. + шлюзы manual/stars (идемпотентно)
ssh <user@host> "cd /opt/vpnshop/app && PYTHONPATH=. .venv/bin/python scripts/seed_demo.py"

# бот жив и на polling
curl -s "https://api.telegram.org/bot<токен>/getMe"
curl -s "https://api.telegram.org/bot<токен>/getWebhookInfo"   # url должен быть пустой
```

Переключатели режимов (между блоками) - с сервера:

```bash
ssh <user@host> "cd /opt/vpnshop/app && PYTHONPATH=. .venv/bin/python scripts/set_config.py КЛЮЧ=значение"
```

Ключи, которые понадобятся: `MAIN_MENU_MODE` (inline/reply), `SALES_MODE` (plans/constructor),
`SUPPORT_MODE` (tickets/redirect/bot/miniapp), `MAINTENANCE_MODE` (true/false).

## А. Базовые экраны (5 мин)

| Что сделать | Что должно быть |
|---|---|
| `/start` | Приветствие + главное меню, кнопки на месте |
| «Подписка» (без подписки) | Заглушка «нет активной подписки» + кнопка «Купить VPN» |
| «Кабинет» | Имя, id, баланс 0, друзей 0 |
| «Серверы» | Список нод мок-панели, все зелёные |
| «История» | «Пока пусто» |
| Условия / Конфиденциальность | Текст открывается, «Меню» возвращает назад |

## Б. Покупка без денег (10 мин)

1. «Купить VPN» -> план -> срок -> способ оплаты. Цена совпадает с тарифом.
2. Оплата «вручную» (manual) -> экран «ожидает подтверждения». Жмём «Проверить оплату»
   до подтверждения: должно ответить «ещё не оплачен», без ошибок.
3. Подтверждаем платёж с сервера (нужен секрет manual-шлюза, задаётся в веб-админке
   в настройках шлюза; id платежа - в веб-админке в транзакциях):

```bash
curl -s -X POST https://<домен-стенда>/api/v1/payments/manual \
  -H "x-admin-secret: <секрет>" -H "content-type: application/json" \
  -d '{"payment_id":"<uuid платежа>","status":"completed"}'
```

4. В боте приходит сообщение об активации. «Проверить оплату» -> подписка активна.
5. Повторить тот же curl ещё раз: ответ спокойный, двойного зачисления нет (смотри «Историю»).
6. Экран «Подписка»: тариф, срок, трафик, ссылка. «Подключить»: инструкции по приложениям.
   «Устройства»: список с мок-панели, удаление работает.
7. **Живой трафик**: накрутить расход на мок-панели и переоткрыть «Подписку» - цифра
   должна вырасти в течение минуты. То же в мини-аппе.

```bash
ssh <user@host> 'curl -s -X PATCH http://127.0.0.1:3010/api/users/<uuid-юзера-панели> \
  -H "content-type: application/json" -d "{\"userTraffic\": 7516192768}"'   # 7 ГБ
```

8. Пополнение: «Баланс» -> Stars -> инвойс открывается (не оплачивать). Затем начислить
   баланс через `/admin` -> Пользователи -> баланс+, купить продление с баланса:
   срок вырос, в «Истории» новая запись.

## В. Промо и подарки (5 мин)

1. Создать промокод в `/admin` -> Промокоды.
2. В боте «Промокод» -> ввести код -> бонус применился (баланс/дни/скидка, что выбрал).
3. Ввести тот же код повторно: «уже использован». Ввести мусор: вежливая ошибка, бот не падает.
4. Gift-код: `/admin` -> Gift-коды -> создать. Ссылку `t.me/<бот>?start=gift_...` открыть
   вторым аккаунтом: подарок активировался.

## Г. Рефералка (3 мин)

1. «Партнёрка»: своя ссылка + счётчики.
2. Перейти по ссылке вторым аккаунтом, нажать `/start`: у первого «друзей: 1».
3. «Вывести» (если включён вывод): форма карта/USDT/TON отправляется, владельцу приходит
   уведомление, заявка видна в веб-админке.

## Д. Триал (2 мин)

Вторым аккаунтом: «Попробовать бесплатно» -> подписка выдана без оплаты, ссылка на месте.
Повторно: «уже использован».

## Е. Поддержка (5 мин)

1. `SUPPORT_MODE=tickets`: «Поддержка» -> написать текст -> тикет виден в веб-админке,
   ответ из админки приходит в чат бота.
2. `SUPPORT_MODE=redirect`: кнопка ведёт на указанный аккаунт.
3. Вернуть `tickets`. `/bug` с любым текстом: админу приходит багрепорт.

## Ж. Админка в боте (5 мин)

| Что сделать | Что должно быть |
|---|---|
| `/admin` | Меню админки (с обычного аккаунта команда молчит) |
| Статистика, Аналитика | Цифры рисуются, не падает |
| Пользователи -> поиск по id | Карточка, баланс+-, продлить, бан/разбан работают |
| Рассылка -> «все» -> текст | Сообщение пришло на оба аккаунта |
| Настройки | Тумблеры щёлкаются, значение реально меняется |
| Обновление | Проверка версии отвечает, не виснет |

## З. Поломочные сценарии (7 мин)

1. `MAINTENANCE_MODE=true`: обычный аккаунт видит заглушку на любую кнопку, админ работает.
   Вернуть `false`.
2. Бан из админки: бот молчит для забаненного. Разбан: снова работает.
3. Спам одной кнопкой (10+ нажатий подряд): бот не падает, лишние нажатия гасятся.
4. Подписка на канал: включить обязательную подписку, неподписанный видит «подпишись»,
   после подписки «Проверить» пропускает дальше. Выключить.
5. Застрявшая форма: открыть «Промокод» (бот ждёт текст), нажать `/start`. Меню работает,
   следующее сообщение НЕ съедается как промокод. То же с формой вывода средств.
6. `MAIN_MENU_MODE=reply`: меню внизу как клавиатура, все пункты работают. Вернуть `inline`.
7. `SALES_MODE=constructor`: «Купить» превращается в конструктор (период -> пакет -> оплата).
   Вернуть `plans`.

## Серверные приёмы (для пунктов выше и вокруг них)

Форс любой фоновой задачи (исполнит живой воркер, смотреть `journalctl -u vpnshop-worker`):

```bash
ssh <user@host> "cd /opt/vpnshop/app && PYTHONPATH=. .venv/bin/python - <<'PY'
import asyncio
from src.infrastructure.taskiq.broker import broker
from src.infrastructure.taskiq import tasks

async def main():
    await broker.startup()
    await tasks.send_expiry_reminders.kiq()   # или любая другая из tasks.py
    await broker.shutdown()

asyncio.run(main())
PY"
```

Напоминание об истечении на свой аккаунт: сдвинуть срок своей подписки под шаг лестницы
(например, шаг 24 часа -> поставить `expire_at` = сейчас + 23:55), форснуть
`send_expiry_reminders`, сообщение придёт в Telegram. Повторный запуск молчит (защита от
дублей), ключи дублей в Redis: `exprem:*`.

Вебхук панели руками (подпись обязана сходиться, иначе 403):

```bash
SECRET=$(grep '^REMNAWAVE__WEBHOOK_SECRET' /opt/vpnshop/app/.env | cut -d= -f2-)
BODY='{"event":"user.modified","data":{"uuid":"<uuid>","status":"ACTIVE","userTraffic":1073741824}}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" -r | cut -d' ' -f1)
curl -s -X POST https://<домен-стенда>/webhook/panel \
  -H "content-type: application/json" -H "x-remnawave-signature: $SIG" -d "$BODY"
```

## Что записывать

На каждый упавший пункт: блок и номер, что нажал, что ожидал, что увидел (скрин), код ошибки
из сообщения бота, если показался. После фикса перегонять только упавшие пункты и всё,
что они трогают.
